#  1. IPOTESI, in italiano
# ---------------------------------------------------------------------
#  Quando la seduta cash apre con un GAP e il prezzo, nel corso della
#  mattina, torna indietro fino a RIATTRAVERSARE la chiusura cash del
#  giorno prima ma NON riesce a restarci -- chiude di nuovo dalla parte
#  del gap -- allora il tentativo di riempimento e' FALLITO e la seduta
#  riparte nella direzione del gap.
#
#  PERCHE' DOVREBBE FUNZIONARE, in una riga:
#    chi ha venduto il riempimento del gap si ritrova in perdita nel
#    momento esatto in cui il livello viene riconquistato, e la sua
#    uscita forzata e' il carburante della seconda gamba.
#
#  🎯 PERCHE' RIEMPIE IL BUCO DEL MANDATO
#    Il ramo GAP-GIU' -> riconquista fallita -> SELL genera il
#    DAX SHORT e il DOW SHORT all'apertura, che nessuna sedia viva ha
#    (R52_CENSIMENTO_LATI: 770101 SOLO LONG, 770202 SOLO LONG, 770611
#    SOLO LONG). Il lato NON e' un input: lo decide il segno del gap.
#
#  E PERCHE' NON E' UNA MISURA CHE ABBIAMO GIA' -- tre differenze:
#    (a) NON e' P0-2 di GAPCASH_NAS_PASSO0 (rimbalzo dei primi 15
#        minuti dopo un gap in giu'): li' si entra ALL'APERTURA, in
#        direzione CONTRARIA al gap, e si esce a tempo. Qui si entra
#        DOPO, alla riconquista fallita, IN DIREZIONE del gap.
#    (b) NON e' P0-5 dello stesso file (lo stesso rimbalzo sul lato
#        opposto, gap >= +0,50%): quella misura e' un FADE, questa e'
#        una CONTINUAZIONE. Le due previsioni sono opposte: se P0-5
#        esce viva, questa deve uscire morta, e viceversa. Sono un
#        controllo l'una dell'altra ed e' un bene, non un doppione.
#    (c) NON e' ABTG_GapFill (772231-772235): quello entra CONTRO il
#        gap puntando al riempimento COMPLETO, con InpFillPct, sul gap
#        del WEEKEND su H1. Qui il gap e' quello della sessione CASH
#        infrasettimanale e la condizione e' che il riempimento
#        FALLISCA.
#    (d) NON e' il pattern OOPS (articolo MQL5 21741, messo in coda
#        oggi dal dossier gemello): li' il riferimento e' l'ESTREMO
#        del periodo precedente e si entra CONTRO l'apertura. Qui il
#        riferimento e' la CHIUSURA cash e si entra A FAVORE del gap.

#  2. COSA DEVE CONTARE LA SONDA (definizioni operative, ORA SERVER)
# ---------------------------------------------------------------------
#  chiusura_cash_ieri = close della barra M30 che finisce a InpCashEnd
#                       dell'ultima seduta buona precedente
#  apertura_cash_oggi = open della barra M30 che comincia a InpCashStart
#  gap%               = (apertura_cash_oggi / chiusura_cash_ieri - 1) x 100
#
#  GIORNATA-EVENTO se |gap%| >= InpMinGapPct.
#  Su una giornata-evento, dentro la finestra InpCashStart ->
#  InpCashStart + InpWindowBars barre, si cerca la RICONQUISTA FALLITA:
#    gap SU  : una barra con low  <  chiusura_cash_ieri
#              e close > chiusura_cash_ieri            -> segnale LONG
#    gap GIU': una barra con high >  chiusura_cash_ieri
#              e close < chiusura_cash_ieri            -> segnale SHORT
#  Il segnale si valuta SOLO su barra CHIUSA (mai la barra in
#  formazione: §4 repaint / look-ahead).
#  Un solo segnale per giornata, il primo.
#
#  E per ogni segnale la sonda registra:
#    - rendimento a +1, +2, +4 barre M30 dalla chiusura del segnale
#    - MAE e MFE nella stessa finestra
#    - lo SPREAD misurato tick per tick nel minuto del segnale
#    - se la giornata e' un lunedi' (per separare il gap del weekend)
