# =====================================================================
#  IPOTESI
# ---------------------------------------------------------------------
#  Nella sessione di Londra su un cambio major il flusso arriva a
#  raffiche. Una chiusura FUORI dal canale stretto formato dalla media
#  a 5 dei massimi e dalla media a 5 dei minimi segnala una raffica
#  appena partita e non ancora finita. Se e' vero:
#    (a) l'evento capita PIU' VOLTE AL GIORNO (l'autore dichiara ~5/gg
#        e cappa a 6 nel sorgente) -> PORTATA;
#    (b) l'escursione favorevole successiva e' abbastanza grande da
#        pagare uno spread di ~1 pip con largo margine -> TAGLIA;
#    (c) il rapporto fra escursione favorevole e avversa e' abbastanza
#        alto da superare il cancello H8 con un win rate PLAUSIBILE
#        (RR 1,875 letto nel sorgente -> serve 37,4% lordo / 42,0%
#        netto a 1 pip di costo) -> GEOMETRIA.
#  Se (a) e' falso il candidato muore per F1 senza scrivere un EA.
#  Se (b) e' falso muore per F2, e con lui muore l'idea che la portata
#  si compri sui major a M5.
#
# =====================================================================
#  CRITERI DI ACCETTAZIONE (CONGELATI IL 31/08 PRIMA DI OGNI NUMERO)
# ---------------------------------------------------------------------
#  F1 - PAVIMENTO DI FREQUENZA (pavimento duro, di Claudio 31/08):
#       segnali per LATO >= 1 al giorno di borsa contato.
#       < 1/giorno  -> SCARTO IMMEDIATO. Niente EA, niente griglia.
#       1-2/giorno  -> PASSA, ma al minimo.
#       > 2/giorno  -> PASSA nella fascia preferita da Claudio.
#       RIFERIMENTO DICHIARATO DALL'AUTORE (non nostro, non un numero
#       di performance): "preferably no more than 5 trades / day".
#
#  F1-bis - ABLAZIONE 1, GRATIS: la sonda conta i segnali DUE VOLTE,
#       col canale NUDO e col canale + conferma RSI. Motivo: l'autore
#       stesso scrive sulla pagina "Then we can OPTIONALLY verify with
#       the RSI", cioe' dichiara l'RSI un FILTRO APPICCICATO -- e in
#       casa il filtro appiccicato a un motore gia' tarato fa
#       0 SUCCESSI SU 5 (ROBUSTEZZA.md par. 5B).
#       Se col RSI acceso i segnali scendono SOTTO 1/giorno, l'RSI
#       UCCIDE IL PAVIMENTO e va tolto PRIMA di qualunque discorso di
#       merito.
#
#  F2 - TAGLIA DEL TAKE (metro di casa C2): mediana dell'escursione
#       FAVOREVOLE a 12 barre dall'ingresso, in PIP.
#       >= 3,0 pip  -> PASSA   (3 x ~1,0 pip di spread di riferimento)
#       <  3,0 pip  -> SCARTO
#       fra 3,0 e 6,0 -> VERDETTO SOSPESO: si misura lo spread VERO col
#                        Code Base 74148 (RealCost Spread P95 Logger,
#                        promosso il 23/08, MAI ancora usato -- e'
#                        la SESTA caccia che lo scrive) e si rilegge.
#       ~1,0 pip e' una CONVENZIONE DI MERCATO, marcata
#       [SPREAD NON MISURATO]: su EURUSD BCM non e' mai stato misurato.
#
#  F3 - ESCURSIONE AVVERSA mediana a 12 barre, in pip: da leggere
#       sempre. Nessun cancello: serve a sapere se lo stop da 8 pip
#       dell'autore sta SOPRA o SOTTO il rumore (pavimento SL, R109).
#
#  F4 - MURO GIORNALIERO PROP: massimo di segnali in UNA giornata.
#       E' il numero che taglia InpMaxTradesPerDay sui DATI, non a
#       occhio. ATTENZIONE: se (max segnali) x 0,65% supera il cap C1
#       di rischio aperto (3,25%, firmato il 18/08), il cap va scritto
#       nell'EA DAL PRIMO ROUND, non aggiunto dopo.
#
#  F4-bis - CANCELLO H8 (FIRMA 2 del 31/08, testuale: "Ogni motore ad
#       alta frequenza entra in flotta SOLO con E >= 0.075R misurata A
#       TICK. Frequenza sotto questo cancello = portata finta (DD e
#       costi)."). La sonda restituisce RR = mediana(favorevole) /
#       mediana(avversa).
#       RR mediano < 0,70 -> SCARTO PER ARITMETICA, e NON si spende
#       una corsa a tick.
#       Tabella congelata, da p >= 1,075 / (RR + 1):
#         RR 0,36 -> serve WR 79,0% | 0,73 -> 62,2% | 1,00 -> 53,8%
#         RR 1,42 -> 44,4% | 1,56 -> 42,0% | 1,875 -> 37,4%
#       La geometria dell'autore (tp=150 / sl=80 tick) da' RR 1,875:
#       e' SOPRA 0,70, quindi il candidato NON e' uno scarto per
#       aritmetica -- ma il RR che conta e' quello MISURATO qui.
#
#  F5 - DUE LATI, SEMPRE E SEPARATI (regola di Claudio del 25/08).
#       Ogni numero ha la sua colonna Long e la sua Short: NESSUN
#       totale aggregato entra in un verdetto.
#       NOTA: l'autore usa soglie RSI ASIMMETRICHE (80 sopra / 10
#       sotto) -> il suo lato short fa molti meno segnali. Da noi la
#       soglia si misura SIMMETRICA.
#
#  F6 - GRADIENTE DI TIMEFRAME, dichiarato prima: la sonda gira su M5
#       E su M15. Attesi piu' segnali e take piu' piccoli a M5. Se la
#       taglia CROLLA a M5, e' il gradiente R108/R111 (H1 > M30 > M15,
#       monotono su 3 simboli) visto dall'altro lato, e va detto.
#
#  F7 - ORA IN ORA SERVER, E SI SWEEPA. Il Pine usa
#       time(res, "0300-1100") SENZA argomento di fuso -> usa il fuso
#       dello SCAMBIO del simbolo, che su un grafico FX di TradingView
#       e' [INCERTO] (UTC oppure New York a seconda del feed).
#       In ORA SERVER BCM (= ora italiana - 1 = UTC+1 in agosto):
#         se il grafico e' UTC  -> 04:00-12:00 server
#         se il grafico e' NY   -> 08:00-16:00 server
#       Entrambe cadono su Londra. L'ora NON si converte a tavolino:
#       si SWEEPA su 3 valori di inizio. E si VERIFICA sull'orologio
#       del server (CLAUDE.md: log MT5 in ora locale, grafico in ora
#       server -- errore gia' pagato il 06/08).
#
