#  COS'E' QUESTA VARIANTE
#    Il piu' stupido dei piani: si entra, si mette lo stop, si mette il
#    TP a 2R e non si tocca piu' niente. Uscite possibili: TP 2R, stop
#    iniziale (2,5 x ATR), flat delle 17:30 server. E' il pavimento
#    contro cui misurare qualunque gestione: una gestione che non batte
#    il "non fare niente" non e' una gestione, e' un'abitudine.
#
#  ATTENZIONE - IL NODO, dichiarato: si usa InpTPfinal_R=2.0
#    La ricetta ovvia (InpTP1_R=2.0 con InpTP1Pct=100) NON e'
#    realizzabile: il blocco della prima parziale pretende
#    InpTP1Pct < 100 (riga 295), quindi a 100 il blocco e' SPENTO e il
#    TP a 2R non esisterebbe affatto - si misurerebbe un "lascia
#    correre" travestito, cioe' la variante B una seconda volta.
#    Si usa invece il TP sull'ORDINE, piazzato alla creazione del
#    pendente (righe 249-251, lato short):
#        double dist = sl - sellPx;                    // = 1R esatta
#        double tp   = NormalizePrice(sellPx - dist*InpTPfinal_R);
#    Con InpTPfinal_R=2.0 il TP e' a 2R esatti dal prezzo del pendente.
#    E' il TP secco VERO, ed e' piu' pulito della ricetta originale.
#
#  CONTROLLO DI COERENZA CHE VALE PER TUTTO IL ROUND
#    F non parzializza mai, quindi il suo numero di "trades" nel CSV E'
#    il numero di POSIZIONI. Deve coincidere con quello di B. Se non
#    coincide, gli ingressi NON sono identici e il round e' invalido.
