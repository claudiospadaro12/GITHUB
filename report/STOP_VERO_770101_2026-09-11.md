## 3.1 🧷 IL LUCCHETTO, in due righe di sorgente `[MISURATO]`

`mql5/Experts/ABTG_DAX_Apertura_EU.mq5`, blocco trailing (r.1981-1995):

```mql5
if(type == POSITION_TYPE_BUY) {
   double newSL = TrailStopBuy(bid);
   if(newSL > 0 && newSL > sl && newSL > openP)      // <-- riga 1986
      gTrade.PositionModify(ticket, NormalizePrice(newSL), tp);
}
else if(type == POSITION_TYPE_SELL) {
   double newSL = TrailStopSell(ask);
   if(newSL > 0 && (newSL < sl || sl == 0) && newSL < openP)   // <-- riga 1992
      gTrade.PositionModify(ticket, NormalizePrice(newSL), tp);

```

E il breakeven (r.1936 e r.1956) mette lo stop **esattamente** a `openP`.

> ### 🔴 **`newSL > openP`. Il trailing non può MAI mettere lo stop nella zona di perdita.**
> Né il trailing né il breakeven possono portare lo stop sotto il prezzo
> d'ingresso di una BUY (o sopra quello di una SELL). Possono solo spostarlo
> **oltre il pari**.
>
> ## 👉 **Quindi: se una posizione chiude IN PERDITA con `close_reason=sl`, quello stop è ANCORA QUELLO INIZIALE. Sempre. Senza eccezioni.**

Questo è il discriminante che stamattina non avevo. Non è una stima: è una
condizione booleana nel sorgente.
